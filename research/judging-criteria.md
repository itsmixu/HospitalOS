# Judging criteria & requirements checklist

Distilled from [challenge-brief.md](challenge-brief.md). Use this to pressure-test ideas.

## Core ask
A focused **everyday** use case where the **first-person field of view** enables new or better interactions — hands-free, in-the-moment, and **beyond simply mirroring a phone screen**.

## Explicit judging criteria
- [ ] **Creativity** — original, relevant use case
- [ ] **Technical execution** — functional prototype
- [ ] **Real-world impact** — clear everyday need, clear audience
- [ ] **Inclusive interaction design** — works for people with all abilities

## Deliverables
- [ ] Clear problem statement + intended audience
- [ ] Functional prototype
- [ ] Deck

## Prototype must handle (called out explicitly)
- [ ] Permissions
- [ ] Errors
- [ ] Performance trade-offs
- [ ] Connectivity (loss / degraded)
- [ ] Device state changes (disconnect, battery, glasses removed, etc.)

## Must show in the demo
- [ ] Clear **wearable benefit** (why glasses, not a phone?)
- [ ] Focused, plausible **path to adoption or a pilot**
- [ ] **Accessibility** baked in
- [ ] **Appropriate consent** (incl. bystanders in camera view)
- [ ] **Safe data practices** within demo scope

## Format — all equal footing
- Display experiences (Meta Ray-Ban Display) **or** audio-first (RBM Gen 2)
- Web apps **or** Device Access Toolkit (DAT) mobile integrations
